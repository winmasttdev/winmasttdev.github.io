RFC test vectors

Verifies this exact code against the published test vectors: all 10 HOTP vectors from RFC 4226 Appendix D (counter 0–9, 6 digits) and all 6 SHA-1 TOTP vectors from RFC 6238 Appendix B (8 digits, 30-second period).

How it works

  1. Base32-decode the shared secret into raw bytes.
  2. Derive the step counter: counter = floor(unixTime / period).
  3. Encode the counter as an 8-byte big-endian integer.
  4. Compute HMAC-SHA1(secret, counter) with WebCrypto.
  5. Dynamic truncation (RFC 4226 §5.3): take the offset from the last HMAC byte (offset = lastByte & 0x0f), read the 31-bit big-endian integer at that offset (high bit masked off), take it modulo 10^digits, and zero pad to digits.

SHA-1 is the default hash of RFC 6238, and it is safe here because the hash is used as a keyed HMAC, not in a collision-sensitive way — an attacker would need the secret, which never leaves your browser.
